# Передача состояния

Portable CI для `pkcs11-tool` и `pkcs11-spy` завершен и находится в `master`.

Текущая следующая задача — [расследование сочетаний режимов и полномочий](PLAN.md).
Владелец передал архив аппаратного прогона 2026-10-21; его разбор — в
[`RUTOKEN-PRIVILEGE-20261021.md`](RUTOKEN-PRIVILEGE-20261021.md).
Успешные CLI-пути `TokenManage` под SO при политиках `admin`/`both`, имена
до 256 байт и оба варианта repair зафиксированы. Исходник приложенного
прямого helper не соответствует ABI, так что mode 4 под USER, сравнение 32-байтовой метки
и инвентарь модели/версий надо повторить штатным
[`rutoken-privilege-probe`](../tests/rutoken-privilege-probe.c). Объектов до
repair было ноль: проверить их удаление можно только с заранее созданным
тестовым объектом. Исправлений CLI по этому архиву пока не требуется.
Для оставшихся двух вопросов подготовлен
[`run_privilege_followup.sh`](../scripts/rutoken/run_privilege_followup.sh)
и [инструкция](../scripts/rutoken/FOLLOWUP-README.md); полный `all`
повторять не нужно.
Изменения сохранены локально в `master`. `make check`
прошёл (12 PASS, 1 SKIP без считывателя), прямая проба и сценарий лицензии
прошли на заглушке. Публикация следующего portable-релиза `.12` пока
не выполнена: облачный прокси на `proxy:8080` отклоняет соединение, а
`gh auth status` не принимает текущий `GH_TOKEN`. После восстановления
доступа отправить этот коммит и запустить `portable-release.yml` с тегом
`0.27.1-portable.12`; затем проверить шесть test kit и 12 ZIP с `SHA256SUMS`.
Уже подтвержденные случаи не повторять без причины. Аппаратные изменяющие
пробы — только на расходном токене. По решению владельца пока не выполнять
новые работы по Flash, BIO (включая `C_EX_*` аутентификацию) и устаревшим функциям.
Никогда не включать в будущую работу ключи эмитента и CRISP. Старые пункты
ниже описывают уже сделанное, а не возобновляют эти направления.

- Опубликованный релиз: <https://github.com/code-agent-43824/OpenSC/releases/tag/0.27.1-portable.11>
  (`pkcs11-spy` теперь показывает имена типов ключей ГОСТ-512, KUZNECHIK,
  MAGMA и механизмов ГОСТ-2012/VKO/HMAC Стрибог). Все шесть платформенных

  32-байтовые ключи; все 11 вызовов `C_DeriveKey` в аппаратном spy-логе
