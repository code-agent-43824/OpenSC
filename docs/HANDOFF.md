# Передача состояния

Portable CI для `pkcs11-tool` и `pkcs11-spy` завершен и находится в `master`.

Расследование [сочетаний режимов и полномочий](PLAN.md) завершено на
проверенном расходном Рутокене ЭЦП; подробный
[разбор заключительной пробы](RUTOKEN-PRIVILEGE-CLOSURE-20261023.md).
Первый аппаратный прогон описан в
[`RUTOKEN-PRIVILEGE-20261021.md`](RUTOKEN-PRIVILEGE-20261021.md),
повторная адресная проба со штатным helper — в
[`RUTOKEN-PRIVILEGE-FOLLOWUP-20261021.md`](RUTOKEN-PRIVILEGE-FOLLOWUP-20261021.md).
На Рутокен ЭЦП (fw 34.2, модуль 2.21) mode 4 под USER/RW с политиками
`user`/`both` дал `CKR_OK`, при `admin` — `CKR_USER_NOT_LOGGED_IN`; изменение
PIN проверено повторным входом. Под SO прежний прогон подтвердил обратную
пару прав. Штатный `C_GetTokenInfo.label` совпал с первыми 32 байтами имени
и для 256-байтовой метки. Поэтому снят запрет USER для `reset-user-pin` в
`pkcs11-tool`, обновлены документация и заглушка. Релиз `.12` затем
проверен на реальном токене: CLI под USER/RW работает. Перед repair был
создан объект, после него счётчик стал `1 → 0`; немедленные входы с новыми
USER и SO PIN успешны. Проверены отрицательные полномочия и сессии, а
имена вплоть до 4096 байт приняты без потерь. Истинный максимальный размер
имени не найден. Повторять эти пробы не нужно.
Для закрытия этих вопросов использована единая неинтерактивная
[`closure`-проба](../scripts/rutoken/CLOSURE-README.md): отрицательные
сочетания полномочий и сессий, граница имени 257+, CLI mode 4 под USER,
удаление созданного объекта при repair и немедленный вход под новым USER PIN.
Аппаратный результат уже разобран в указанном отчёте; новых дефектов CLI
не найдено. Отдельный прогон SoftHSM `FAKE_RUTOKEN_ECP` имеет собственный
предел имени 255 байт и не поддерживает mode 4. Заглушка OpenSC обновлена
по результату настоящего токена, с проверкой имени 4096 байт.
Автономный Linux x64 комплект опубликован отдельно от portable-релизов:
[`rutoken-privilege-closure-20261022`](https://github.com/code-agent-43824/OpenSC/releases/tag/rutoken-privilege-closure-20261022).
Скачанный с GitHub ZIP повторно совпал по SHA-256
`11c26e57ff088cc2dfbc9444049d23a2da3e4775cbcb0c6963b23a0031fb49cd`.
Изменения в `master` и опубликованном релизе
[`0.27.1-portable.12`](https://github.com/code-agent-43824/OpenSC/releases/tag/0.27.1-portable.12)
(коммит `20e15f319`). Локальный `make check` прошёл (13 unit PASS;
4 integration PASS, 9 SKIP без нужных внешних модулей/считывателя), включая
тест расширения Рутокен на заглушке. [Релизный workflow](https://github.com/code-agent-43824/OpenSC/actions/runs/39747845192)
завершился успешно: шесть сборок и шесть независимых clean-runner проверок.
Все 12 опубликованных ZIP скачаны заново и совпали с `SHA256SUMS`, прошли
проверку CRC и состава; Linux x64 test kit повторно прошёл вне CI.
Уже подтвержденные случаи не повторять без причины. Аппаратные изменяющие
пробы — только на расходном токене. По решению владельца пока не выполнять
новые работы по Flash, BIO (включая `C_EX_*` аутентификацию) и устаревшим функциям.
Никогда не включать в будущую работу ключи эмитента и CRISP. Старые пункты
ниже описывают уже сделанное, а не возобновляют эти направления.
