# Статус

Реализован workflow portable-релиза `pkcs11-tool` и `pkcs11-spy` для Linux x64/ARM64, Windows x86/x64/ARM64 и macOS universal. Сборки статически включают сторонние библиотеки; Windows-архивы содержат требуемую проектную `opensc.dll` рядом с executable. PE/ELF/Mach-O файлы проверяются на архитектуру и отсутствие незапланированных динамических зависимостей.

Каждый архив перед публикацией передается на отдельный чистый runner. Проверка скачивает соответствующий обычный архив последнего релиза `code-agent-43824/SoftHSMv2`, собирает плоский автономный `opensc-testkit-<platform>` и запускает сценарий именно из него. В test kit входят portable-инструменты OpenSC, модуль SoftHSM, `test.py`, manifest платформы и инструкция. Сценарий выполняется напрямую и через `pkcs11-spy` с проверкой лога.

`pkcs11-spy` поддерживает локальный `pkcs11-spy.conf` рядом с модулем:
полный распознанный файл имеет приоритет над environment и Windows Registry,
а отсутствующий или некорректный файл сохраняет прежнее поведение. В portable
product и вложенном test-kit package поставляется безопасный закомментированный
шаблон. Приоритет файла и fallback проверены на всех шести платформах.

Полный GitHub Actions прогон [`32370121050`](https://github.com/code-agent-43824/OpenSC/actions/runs/32370121050) успешен: шесть build, шесть clean-runner verify и release job завершились с `PASS`. Все 12 Actions artifacts доступны напрямую, без вложенных ZIP.

Релиз [`0.27.1-portable.4`](https://github.com/code-agent-43824/OpenSC/releases/tag/0.27.1-portable.4) содержит шесть product ZIP, шесть test-kit ZIP и общий `SHA256SUMS`. Все assets скачаны заново: 12 хэшей совпали, вложенных ZIP нет, шаблон конфигурации присутствует во всех архивах, Linux x64 test kit повторно прошел вне CI.

Workflow выпуска не имеет тега по умолчанию и не перезаписывает опубликованное:
первый job за секунды отклоняет тег не формата `X.Y.Z-portable.N`, уже
существующий Git-тег или релиз; release-job повторяет проверку и только создает
новый релиз, без `--clobber`.

Из GitHub Actions выключены 14 общих upstream-workflow. Активны только portable release для обеих утилит и `Tests of external pkcs11 modules`, который непосредственно проверяет `pkcs11-tool`; его push-trigger ограничен изменениями исходного кода и build-файлов.

Официальные расширения Рутокен 2.19.0.0 изучены и описаны в [`RUTOKEN-EXTENSIONS.md`](RUTOKEN-EXTENSIONS.md). В [`PLAN.md`](PLAN.md) добавлена поэтапная полная поддержка 33 указателей расширенной таблицы в `pkcs11-spy` и `pkcs11-tool`, включая семь устаревших ABI-функций, безопасную обработку секретов и аппаратную приемку.

Первая часть реализации расширений готова: общий загрузчик разрешает
`C_EX_GetFunctionListExtended`, `pkcs11-spy` экспортирует и проксирует все 33
указателя ABI 2.19.0.0 с редактированием секретов, а `pkcs11-tool` предоставляет
первые read-only команды `--rutoken-info` и `--rutoken-name`. Локально сверены
ABI-размеры и смещения, spy проверен через свежую сборку portable SoftHSM;
автоматический Rutoken driver проверяет все 34 поля таблицы и вызывает через
spy все 33 операции. Он входит во все шесть test kit и успешно выполнен в
прогоне `32347619229`.

Этап 1 завершен: `pkcs11-rutoken.h` описывает все структуры и константы
расширения, включая добавленные в 2.21; размеры, смещения полей и значения
сверены с заголовками 2.19.0.0 и 2.21.3.0 для семи ABI без расхождений. Для
этапов 3–5 по документации Aktiv, примерам SDK и настоящей библиотеке 2.21.3.0
составлено описание функций и команд [`RUTOKEN-FUNCTIONS.md`](RUTOKEN-FUNCTIONS.md).
Библиотека 2.21 дополнительно экспортирует BIO-расширение `C_BIO_*`, которое
spy пока не проксирует.

Read-only программа [`tests/rutoken-hw-probe.c`](../tests/rutoken-hw-probe.c)
прогнана владельцем на Рутокен ЭЦП 3.0 5100 Flash с библиотекой 2.21 для
Linux ARM64 и APDU-трассой pcscd. Ответы внесены в `RUTOKEN-FUNCTIONS.md`, а
команды, которыми библиотека реализует функции расширения, — в
[`RUTOKEN-APDU.md`](RUTOKEN-APDU.md); PIN и уникальные значения устройства в
репозиторий не попали.

Этап 3 реализован: `pkcs11-tool` получил `--rutoken-license`,
`--rutoken-journal`, `--rutoken-volumes`, `--rutoken-cert-text`,
`--rutoken-pin-status` и JSON-вывод `--rutoken-json` для всех команд
`--rutoken-*`; `--rutoken-info` расшифровывает константы. Лицензия пишется
только в файл с правами владельца. Spy логирует результаты функций чтения,
кроме лицензий. Заглушка реализует эти функции, команды проверяются в
`make check` и во всех шести test kit. На проверенном токене библиотека
отвечает на полный запрос разделов `CKR_TOKEN_NOT_PRESENT`, поэтому
`--rutoken-volumes` покажет объем, число разделов и эту ошибку; сертификатов
и записей журнала для проверки не было.

Версия 2 probe прогнана на том же токене с `--write-tests`: 117 шагов без
ошибок, временные ключ ГОСТ и сертификат созданы и удалены. Получены
непустой журнал, текст сертификата, PKCS#7, CSR, лицензии 3 и 4, коды
незаданного локального PIN и неверных типов пользователей; трасса дала
команды генерации ключа, подписи, хэша, проверки и формат хранения объектов
библиотекой. `C_EX_GetVolumesInfo` заполняет только первый раздел: разбор
записей библиотекой не совпадает с форматом токена. Заглушка приведена к
кодам устройства.

Этап 4 реализован: `--rutoken-pkcs7-sign`, `--rutoken-pkcs7-verify` и
`--rutoken-csr` с текстом и JSON, `--rutoken-confirm-by-touch` для
`--keypairgen` на токенах с кнопкой; spy логирует данные, конверты, строки
CSR и хранилище проверки. Биометрия и разделы Flash отложены.

Probe 3 прогнана владельцем на втором токене — Рутокен ЭЦП 3.0 3127 USB без
Flash, библиотека 2.21 для Linux x64 — во всех трех режимах. Чтение и запись
совпали с первым токеном. Изменяющие функции работают; уточнено поведение:
имя до 255 байт, лицензии 1–4 по 72 байта под входом Пользователя, локальный
PIN меняется только по текущему значению, сброс PIN к умолчанию требует
права Администратора на смену PIN Пользователя, форматирование сохраняет
лицензии и журнал, атрибут кнопки на токене без нее отвергается. Команды
токена разобраны в `RUTOKEN-APDU.md`, заглушка отвечает так же.

Этап 5 реализован: `--rutoken-set-name`, `--rutoken-set-license`,
`--rutoken-set-local-pin`, `--rutoken-unblock-user-pin`,
`--rutoken-token-manage`, `--rutoken-init-token` и
`--rutoken-restore-factory-defaults` с текстом и JSON. PIN для функций,
получающих их напрямую, берутся из `env:` или вводятся без эха; отдельного
подтверждения стирающие команды по решению владельца не требуют. Spy расшифровывает параметры форматирования и режимов управления, PIN и
ключ эмитента — только длиной. Команды проверены на заглушке в `make check`
и в test kit; на устройстве еще не запускались. Не реализованы устаревшие
функции и отложенные разделы Flash.

## Решения по сопровождению

- С upstream OpenSC форк не синхронизируется и изменения туда не отправляет;
  отставание от upstream и соответствие его стилю кода не отслеживаются.
- Verify-jobs намеренно берут последний релиз `code-agent-43824/SoftHSMv2`:
  проекты развиваются параллельно и подтягивают друг друга.
- Команды `--rutoken-*`, которые стирают данные или сбрасывают PIN,
  выполняются без отдельного подтверждения.
