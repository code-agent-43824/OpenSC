## Расширенные функции PKCS #11 Рутокен

Полный перечень, ABI, требования к CLI, spy и тестам зафиксированы в
[`RUTOKEN-EXTENSIONS.md`](RUTOKEN-EXTENSIONS.md), поведение и команды для
этапов 3–5 — в [`RUTOKEN-FUNCTIONS.md`](RUTOKEN-FUNCTIONS.md). Основа —
официальные заголовки Aktiv для `rtPKCS11ECP` 2.19.0.0; в 2.21.3.0 таблица
функций та же.

### Этап 1 — ABI и обнаружение

- [x] Независимо описать типы, константы, 33 сигнатуры и
  `CK_FUNCTION_LIST_EXTENDED`, не копируя заголовки вендора. Размеры,
  смещения всех полей и значения констант сверены с заголовками 2.19.0.0 и
  2.21.3.0 для Linux, macOS и Windows x86/x64/ARM64.
- [x] Добавить compile-time ABI-проверки для Windows x86/x64/ARM64 и Unix
  x64/ARM64, а также модуль-заглушку с эталонной таблицей.
- [x] Научить общий загрузчик опционально находить
  `C_EX_GetFunctionListExtended`, не меняя поведение обычных модулей.

### Этап 2 — полная прозрачность `pkcs11-spy`

- [x] Экспортировать расширенную точку входа и вернуть таблицу из 33 оберток в
  точном порядке ABI 2.19.0.0.
- [x] Передавать и безопасно логировать все актуальные и семь устаревших
  функций; секретные значения по умолчанию редактировать.
- [x] Проверить каждый указатель таблицы модулем-заглушкой, включая ошибки,
  двухпроходные буферы и вызовы до `C_Initialize`.
- [x] Экспортировать и проксировать BIO-расширение библиотеки 2.21:
  `C_BIO_GetFunctionListBio` и 15 функций `C_BIO_*`.

### Этап 3 — безопасный read-only CLI `pkcs11-tool`

- [x] Добавить обнаружение расширения и первые команды для
  `GetTokenInfoExtended` и `GetTokenName`.
- [x] Добавить команды для `GetLicense`, `GetJournal`, `GetVolumesInfo`,
  `GetDriveSize`, `GetCertificateInfoText` и режимов чтения `SlotManage`
  (принудительная смена PIN, локальные PIN).
- [x] Добавить текстовый и JSON-вывод с фиксированными тестами сериализации;
  spy логирует результаты этих функций, кроме содержимого лицензий.
- [x] Проверить на устройстве текст сертификата и непустой журнал, для
  `--rutoken-volumes` выяснить причину `CKR_TOKEN_NOT_PRESENT` (probe 2:
  разбор записей разделов библиотекой не совпадает с форматом токена).

### Этап 4 — криптография и аутентификация

- [x] Получить на устройстве результаты `PKCS7Sign`, `PKCS7Verify*`,
  `CreateCSR`, текста сертификата и непустого журнала: probe 2 с
  `--write-tests` на временных ключе и сертификате.

- [x] Добавить команды `PKCS7Sign`, все четыре `PKCS7Verify*`, `CreateCSR` и

  spy для них.
- [x] Для токенов с кнопкой (Рутокен Touch, `TOKEN_FLAGS_HAS_BUTTON`) —

### Этап 5 — изменяющие и разрушительные операции

- [x] Получить на устройстве поведение изменяющих функций: probe 3 с
  `--modify-tests` (имя, локальные PIN, лицензии, разблокировка, управление
  PIN, форматирование, сброс к заводским настройкам, ключ с кнопкой) — на
  Рутокен ЭЦП 3.0 3127 USB, ответы в `RUTOKEN-FUNCTIONS.md` и
  `RUTOKEN-APDU.md`, заглушка приведена к ним.
- [x] Добавить `InitToken`, `UnblockUserPIN`, `SetTokenName`, `SetLicense`,
  `SetLocalPIN`, `TokenManage` и режим `MODE_RESTORE_FACTORY_DEFAULTS` без
  отдельного подтверждения (решение владельца): команды
  `--rutoken-set-name`, `--rutoken-set-license`, `--rutoken-set-local-pin`,
  `--rutoken-unblock-user-pin`, `--rutoken-token-manage`,
  `--rutoken-init-token`, `--rutoken-restore-factory-defaults`; PIN только
  из `env:` или ввода без эха; spy расшифровывает параметры, скрывая PIN и
  ключ эмитента.
- [x] Прогнать команды этапа 5 `pkcs11-tool` на токене, который можно
  стереть: владелец прогнал релиз `0.27.1-portable.5` на Рутокен ЭЦП 2.0
  (serial 4894721a). Чтение, PKCS#7/CSR на ГОСТ и все изменяющие команды,
  включая аварийный repair, работают; замечания сведены в раздел «Полевой
  отчёт» `RUTOKEN-FUNCTIONS.md`.
- [x] Исправления по полевому отчёту: чтение открытого ГОСТ-ключа через
  `CKA_VALUE`; SO-логин сам открывает R/W-сессию; подсказка про `--login`
  при «object not found»; проверка `--rutoken-min-pin-length` по окну длины
  PIN устройства; repair сам доводит SO PIN до блокировки и делает новые PIN
  необязательными (генерирует и показывает один раз); режим `--test-login`;
  в `pkcs11-spy` — строка версии форка, итоговая статистика вызовов и
  явный `PKCS11SPY_UNSAFE_SECRETS` для отладки без скрытия секретов.
- [ ] Добавить явно помеченные legacy-команды для семи устаревших функций,
  сохранив полную совместимость spy и таблицы. Владелец считает реализацию
  этих команд маловероятной; это не текущий приоритет. Существующая
  совместимость spy и таблицы сохраняется.

### Отложено — разделы Flash

По решению владельца работа с разбиением Flash на разделы отложена;
`--rutoken-volumes` остается как есть (объем, число разделов и ошибка
библиотеки).

- [ ] `FormatDrive` и `ChangeVolumeAttributes` в `pkcs11-tool` с повторным
  поиском токена после переподключения.
- [ ] Собственный разбор таблицы разделов (`80 53 11`, размер в байтах
  [2..3] — гипотеза из `RUTOKEN-APDU.md`) вместо неработающего
  `C_EX_GetVolumesInfo`; сверить размеры с `lsblk` на устройстве.
- [ ] Подробный лог spy для `FormatDrive` (разметка `pInitParams`).

### Биометрия

Владелец сообщил о совместимом BIO-устройстве 2026-10-06. Реализовано
BIO-проксирование в spy и базовые команды BioLib в `pkcs11-tool`:
`--rutoken-bio-scanners`, `--rutoken-bio-authenticate`,
`--rutoken-bio-deauthenticate`, `--rutoken-bio-unblock`. Они проверены на
заглушке. Прогон на устройстве, регистрация отпечатка и подпись ключом,
защищённым биометрией, ещё не выполнены.

- [ ] `Authenticate`, `Deauthenticate`, `UnblockAuthenticator` и безопасный
  ввод аутентификационных данных через объекты расширения `C_EX_*` в
  `pkcs11-tool`; это отдельный API от `C_BIO_*`, spy уже скрывает данные
  `C_EX_Authenticate`.
