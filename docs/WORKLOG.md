## 2026-08-20 — локальный конфигурационный файл pkcs11-spy

План: добавить минимальный parser файла `pkcs11-spy.conf` в каталоге самого
spy-модуля. Файл считается пригодным только при наличии ровно распознаваемых
`PKCS11SPY` и `PKCS11SPY_OUTPUT`; комментарии и пустые строки разрешены,
относительные пути вычисляются от каталога модуля. При отсутствующем,
неполном или некорректном файле сохраняется прежний поиск через environment и
Windows Registry. Проверить приоритет файла и fallback на всех шести clean
runner, положить безопасный полностью закомментированный шаблон в product и
test-kit artifacts и выпустить `0.27.1-portable.4`.

Реализовано: библиотека находит собственный каталог через
`GetModuleFileNameA` на Windows и `dladdr` на поддерживаемых Unix, разбирает
только две разрешенные строки без выполнения shell-синтаксиса и принимает
файл только целиком. Если файл не найден, неполон, содержит неизвестную или
повторную переменную либо для указанного output нельзя открыть файл,
используются прежние environment/Registry источники. Относительные пути
привязываются к каталогу spy-модуля.

В каждый portable product добавлен полностью закомментированный
`lib/pkcs11-spy.conf`; test kit получает тот же файл внутри
`opensc-package`. Сценарий на clean runner теперь отдельно доказывает, что
валидный файл перекрывает заведомо неверный environment, а неизвестная строка
возвращает прежнее environment-поведение. Локально обе ветки пройдены через
свежесобранный spy и полный опубликованный Linux x64 test kit. Остаются полный
CI и выпуск portable.4.

## 2026-08-14 — portable pkcs11-tool и pkcs11-spy

План: собрать и упаковать `pkcs11-tool` и `pkcs11-spy` для шести целевых платформ, затем на отдельных чистых runner проверить прямой сценарий с обычным portable-архивом последнего релиза SoftHSMv2 и тот же сценарий через spy-модуль с валидацией лога.

Сделано: изучены текущие workflow OpenSC, portable workflow и состав релиза SoftHSMv2 `v2.7.0-portable.23`, интерфейс команд `pkcs11-tool` и переменные `PKCS11SPY`/`PKCS11SPY_OUTPUT`. Добавлены платформенные сборочные скрипты, один кроссплатформенный функциональный тест и workflow из build/verify/release стадий. Тест инициализирует SO/User PIN, меняет User PIN через `C_SetPIN`, записывает, читает, сравнивает и удаляет data object; spy-проход требует успешные `C_InitToken`, `C_InitPIN`, `C_SetPIN`, `C_CreateObject`, `C_GetAttributeValue` и `C_DestroyObject` в правильном порядке. Прямой сценарий локально прошел на обычном архиве SoftHSMv2 `v2.7.0-portable.23`; Python, shell и workflow прошли статические проверки.

Первый полный workflow обнаружил платформенное расхождение: macOS strict-сборка с отключенным secure messaging считала условно неиспользуемую функцию ошибкой. Portable-конфигурация отделена от штатного strict CI с помощью `--disable-strict`.

Второй macOS build прошел обе компиляции для ARM64 до упаковки и подтвердил, что libtool-модуль `pkcs11-spy` не обязан иметь суффикс `.dylib` в build tree. Скрипт теперь находит фактический модуль и переименовывает его в стабильное имя пакета.

Linux static-stage дошел до линковки и выявил неправильный для `libcrypto.a` порядок библиотек в посторонних OpenSC tools. Сборка сужена до нужной цепочки и `pkcs11-tool`, где `libcrypto.a` явно повторена после внутренних статических архивов.

Windows x64 полностью собрал и проверил оба целевых файла, но build-step упал уже после создания ZIP из-за недоступного `Get-FileHash` внутри Visual Studio environment. Диагностический расчет заменен на системный `certutil`.

Третий запуск собрал все шесть вариантов; Linux и macOS успешно прошли функциональный тест. Все три Windows теста на чистых runner выявили код загрузчика `0xC0000135`: штатный `Makefile.mak` связывает `pkcs11-tool.exe` с проектной `opensc.dll`, хотя зависимости vcpkg статические. DLL добавлена рядом с executable, включена в архитектурную/dependency-проверку и обязательную проверку состава release-архива.

Четвертый полный запуск `31812435688` успешен на всех платформах. В каждом из шести verify-логов есть итоговый `PASS: direct and pkcs11-spy data-object scenarios completed`.
