# Заключительная неинтерактивная проба полномочий

`run_privilege_closure.sh` проверяет оставшиеся неоднозначные ячейки на
**пустом расходном Рутокене ЭЦП**. Нужны Linux, `cc`, Python 3, модуль
`librtpkcs11ecp.so` и `pkcs11-tool` релиза `0.27.1-portable.12` или новее.
Комплект содержит штатный C helper с правильным ABI и собирает его локально.

Проверяются вызовы `TokenManage` mode 4 без входа и при R/O-сессии,
`SetLicense` без входа и при R/O-сессии, граница имени начиная с 257 байт,
исправленный CLI `reset-user-pin` под USER/RW, а также удаление созданного
тестового объекта при repair и немедленный вход под обоими явно заданными
новыми PIN. У уже закрытых сочетаний из прежних прогонов нет повторных
разрушающих вызовов. Flash, BIO, устаревшие функции, ключи эмитента и CRISP
не вызываются.

Сценарий сначала сверяет серийный номер, оба текущих PIN и нулевые счётчики
объектов без входа, под USER и под SO, затем ищет **пустой** лицензионный слот.
Если пустого слота нет,
лицензионные вызовы пропускаются и итоговый статус `incomplete`; остальные
проверки выполняются. Действующие лицензии не перезаписываются. Тестовая
лицензия на диск и в модуль передается как 72 одинаковых байта; положительной
записи нет. Если отрицательный вызов неожиданно выполнится, прогон
останавливается. При поиске границы имени проверяются чтение после каждого
вызова и возврат исходного имени. Поиск ограничен 4096 байтами.

Затем сценарий один раз форматирует токен с политикой `both`, проверяет
исправленный CLI под USER, создаёт временный объект данных, намеренно
блокирует SO PIN и выполняет repair с заданными новыми PIN. **Форматирование
и repair стирают все объекты и локальные PIN.** При нормальном завершении
сохраняются исходное имя, политика `both`, новые SO/USER PIN из переменных
`RT_NEW_SO_PIN` и `RT_NEW_USER_PIN`; тестовый объект удалён. Лицензии на
устройстве остаются прежними.

Нужны пять переменных окружения:

- `RT_SO_PIN`, `RT_USER_PIN` — PIN, действующие **до** пробы;
- `RT_NEW_SO_PIN`, `RT_NEW_USER_PIN` — PIN после форматирования/repair;
- `RT_DEFAULT_USER_PIN` — отдельный тестовый PIN по умолчанию, отличный от
  обоих USER PIN.

Не добавляйте PIN в аргументы командной строки. Например:

```sh
set -a
. /path/to/private-rutoken-env
set +a
./run_privilege_closure.sh \
  ./pkcs11-tool /path/to/librtpkcs11ecp.so \
  1 HEX_СЕРИЙНОГО_НОМЕРА /path/to/new-private-result-dir
```

Серийный номер и номер слота можно взять из предыдущего отчёта и запуска.
Каталог результата должен отсутствовать. После запуска пришлите архив
**всего** каталога результата. `report.json` содержит стадии, числовые
`CK_RV`, SHA-256 программы, модуля и helper, модель, версии и счетчики;
сырые выводы, PIN, имена и содержимое объектов в отчет не пишутся.
`helper-used` — ровно исполнявшийся helper. `status=complete` означает
завершение всех проверок, но выводы о поведении делаются по отдельным строкам
и сводке `closure`. При прерывании `status=stopped` и `reason` показывают
место остановки; токен мог остаться с блокированным SO PIN или промежуточным
USER PIN. Не запускайте пробу повторно вслепую: сначала сверьте состояние
по отчёту. Каталог результата держите приватным из-за сведений об устройстве.
